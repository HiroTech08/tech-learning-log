# `git push --force` とは何か

## 1. Gitの「履歴」とは

Gitのコミットは、**前のコミットへの参照を持つ鎖のような構造**です。

```
A → B → C → D
```

それぞれのコミットは一意のハッシュID（例: `Abc123`）を持ち、「自分の前は誰か」という情報を内部に持っています。

---

## 2. 通常の `git push` の挙動

通常の push は、**リモートの履歴を継続する形でのみ**受け付けます。

### ✅ 成功するケース

ローカルがリモートより先に進んでいる場合はそのまま push できます。

```
ローカル:  A → B → C → D
リモート:  A → B → C
                      ↑ CのあとにDを追加 → OK
```

### ❌ 拒否されるケース

他の人がリモートに先に push していた場合は拒否されます。

```
同僚が先にpush：
リモート:  A → B → C   ← 同僚のコミットCが追加済み
自分:      A → B → D   ← 自分はCを知らない

この状態で自分がpushしようとすると：
→ 「CをすっとばしてDを置いたらCが消えてしまう」として拒否される
```

**正しい対処：** `git pull` でCを取り込んでから push する。

```
git pull 後：
自分:  A → B → C → D   ← CとDが両方残る

→ この状態なら push できる
```

---

## 3. `git commit --amend` とは

`--amend` は**直前のコミットをやり直す**コマンドです。

### よくある使いどころ

```bash
# コミットメッセージをtypoしてしまった
git commit -m "ログイン機能を追化"  # ← typo！

# amendで直前のコミットをやり直し
git commit --amend -m "ログイン機能を追加"
```

ファイルの修正漏れにも使えます。

```bash
# コミット後に修正漏れに気づいた
git add 修正漏れファイル.ts
git commit --amend  # 直前のコミットに含めてやり直す
```

### amend の内部で何が起きているか

amend は「編集」ではなく、**古いコミットを捨てて新しいコミットを作り直す**操作です。

```
amend 前:  A → B → C → D   （ハッシュ: Abc123）
amend 後:  A → B → C → D'  （ハッシュ: Xyz789）

→ D は消えて、D' という別物が生まれる
```

---

## 4. `--force` が必要になる理由

amend を実行した時点で、**ローカルでは D はすでに消えています。**

```
ローカル:  A → B → C → D'  （amend済み）
リモート:  A → B → C → D   （元のまま残っている）
```

この状態で通常の push をしようとすると：

> 「D' は C の次として作られているが、リモートには C の次に D がある。DをすっとばしてD'を置くことはできない。」

→ **拒否される。**

`--force` をつけると、リモートの D を強制的に D' で上書きできます。

```
--force 実行後：
リモート:  A → B → C → D'  （D は消えた）
```

### 重要：消すのは `--force` ではなく `--amend`

| タイミング | 何が起きるか |
|---|---|
| `git commit --amend` 実行時 | **ローカルで D が消えて D' になる** |
| `git push --force` 実行時 | リモートの D を D' で上書きする |

`--force` が D を消すのではなく、**amend が D を消す。** `--force` はその結果をリモートに反映するために使う道具です。

---

## 5. 普通のコミットとの比較

「D を消さずに D' を push したい」場合は、amend せず**普通に新しいコミットを作る**だけです。

```bash
git commit -m "追加の修正"  # amend せず新規コミット
```

```
ローカル:  A → B → C → D → D'  ← D は残る
```

この場合は通常の push でそのまま送れます。

### まとめ

| 操作 | ローカルの履歴 | リモートへの push |
|---|---|---|
| 普通に新規コミット | `A→B→C→D→D'`（D は残る） | ✅ 通常の push で OK |
| `git commit --amend` | `A→B→C→D'`（D は消える） | ❌ `--force` が必要 |

---

## 6. `--force` の危険性

`--force` はリモートの現状を無視して上書きするため、**共有ブランチで使うと他の人の作業を破壊します。**

```
同僚のローカル:  A → B → C → D → E  ← D を土台に作業中
自分が --force:  A → B → C → D'     ← リモートの D が消えた！

→ 同僚の E の土台だった D がリモートに存在しなくなり、
  同僚が pull しようとすると矛盾した状態になる
```

---

## 7. より安全な代替：`--force-with-lease`

`--force` の危険を軽減した代替オプションです。

```bash
git push --force-with-lease
```

**自分が知らないコミットがリモートにあれば失敗してくれます。** 完全な保護ではありませんが、`--force` より安全です。

---

## 8. 使い分けのまとめ

| コマンド | 用途 | リスク |
|---|---|---|
| `git push` | 通常の作業 | 低 |
| `git push --force` | amend / rebase 後に個人ブランチを更新 | 高（共有ブランチでは禁忌） |
| `git push --force-with-lease` | force が必要だが少しでも安全にしたい | 中 |

### 原則

> **`--force` は自分一人しか触らない個人ブランチ以外では使わない。**
